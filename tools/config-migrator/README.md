# BedWars 配置迁移工具

此独立工具把 1.21.11 的 YAML 配置值合并进 1.8.8 插件生成的目标配置模板。它不启动服务器，不修改输入文件。普通配置不复制现代 `config-version`；`upgrades2.yml` 会保留此字段作为价格来源版本，并重置旧版独立的 `price-schema`，供插件首次加载时迁移升级价格。

需要 Java 21 或更新版本。先运行一次 1.8.8 服务器生成配置，然后停服并执行：

1.8.8 插件 1.3.3 起可识别现代配置版本 8、9、10 的历史锋利升级价格，以及旧版护甲默认价格。只有完整四档价格与该版本旧默认一致且货币未自定义时才更新；修改过任一档的价格组保持原值。缺少的锋利、护甲档位补入当前默认值，已有显示物品、动作和货币保留。无来源版本时不会猜测锋利价格属于哪个历史版本；`price-schema: 1` 的旧版配置也不会重新执行已经完成的护甲迁移。

```text
java -jar bedwars-config-migrator-1.0.0.jar <1.21插件数据目录> <1.8插件数据目录>
```

工具自动递归查找两个目录中的 YAML。`Cache/` 会主动跳过，由 1.8.8 插件重新获取地图缓存。普通配置只合并两个目录里相对路径相同的文件；`Arenas/` 下目标版尚不存在的新地图会从现代文件生成旧版文件，并移除现代架构版本字段、旧版不读取的 `minInTeam`，补齐旧版游戏规则。语言文件中同路径且类型兼容的值始终使用 1.21.11 的值，目标文件缺少的新版标量键也会补入；结构类型冲突会保留目标结构并记录。迁移结果直接写入 1.8 插件数据目录中对应的配置文件，并在该目录生成 `migration-report.txt`。普通配置以现有 1.8 模板为目标结构；旧版不支持或结构不兼容的路径会列在报告中。对材料名和声音名执行的已知映射也会记录在报告里。

工具会直接覆盖目标目录里存在对应模板的配置文件，也会直接创建新竞技场文件。先停止 1.8.8 服务器并备份两个插件目录，再传入插件数据目录本身，而不是 `plugins/` 父目录。检查 `migration-report.txt` 中的未迁移项和映射结果后，启动服务器加载配置。该工具不会自动转换竞技场坐标、物品附魔/自定义数据、代理设置或数据库内容。
